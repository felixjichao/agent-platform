# L4 执行策略 / 执行框架

> **L4 负责策略控制：基于当前决策上下文，决定下一步准备怎么推进；它不负责可靠地让下一步发生。**

## L4 回答什么问题

L4 只回答一个核心问题：

> **基于当前已经知道的信息，下一步准备怎么推进？**

它与相邻两层的职责边界是：

```text
L4 策略控制
→ 选择下一步怎么推进

L3 执行生命周期控制
→ 推进运行、动作、等待、恢复、取消和终止

L2 真实执行
→ 让动作真正发生，并形成观察与验证
```

因此：

> **L4 负责选择，L3 负责推进，L2 负责作用于世界。**

实现可以把这些行为放在同一个进程、类库甚至循环中，但架构归属由控制权、生命周期和副作用边界决定，而不是由类名或包名决定。

## 三个核心语义

L4 Core 只固定三个语义：

```text
L4 执行策略
│
├── 执行框架
│   └── 一个具体的执行策略实现
│
├── 策略状态
│   └── 为保持后续决策连续性维护的私有状态
│
└── 决策
    └── 下一步执行意图
```

规划、待办、工作流图、智能体循环、上下文策略、反思、模型调用、PTC、多智能体编排都可以是执行框架内部机制或执行策略模式，但不是 L4 Core 的统一领域实体。

### 执行框架

执行框架是执行策略的实现载体。它可以由代码、规则、工作流图、模型、多个模型或这些机制的组合实现。

执行框架拥有的是**策略控制**，不是执行生命周期控制。它可以决定：

- 下一步选择什么能力；
- 是否并行产生多个相互独立的动作意图；
- 是否需要继续规划、反思或切换内部策略；
- 是否应该等待已有条件；
- 是否认为当前运行已经可以完成；
- 是否认为当前策略已经没有合理继续路径。

它不能直接修改运行、动作、执行尝试等运行时事实，也不能自行把“动作超时”解释成“动作没有产生副作用”。

### 策略状态

策略状态是执行策略为了保持后续决策连续性维护的私有状态，例如：

```text
工作流
→ 当前节点 / 分支变量

规划器
→ 计划 / 当前游标 / 重规划状态

智能体
→ 待办 / 当前假设 / 操作模式

多智能体策略
→ 委派计划 / 聚合状态
```

策略状态必须显式声明作用域。常见作用域至少包括：

```text
运行级
→ 当前运行内部的策略连续性

会话级
→ 跨多个运行仍需要保留的待办、操作模式或长期策略连续性
```

但无边界的策略状态不能替代记忆、会话历史、工作单元状态或工作空间状态：

```text
策略状态
→ 策略准备怎么继续

运行时状态
→ 执行实际上进行到哪里

会话历史
→ 已经发生过哪些交互

记忆
→ 需要跨时间保留的信息

工作空间
→ 真实工作世界的持续状态
```

### 决策

决策是执行框架向运行时返回的下一步执行意图。它是**意图**，不是已经发生的事实。

推荐保持最小集合：

```text
Execute(actions)
Cancel(targets)
Wait(condition)
Complete(output, evidence_refs)
Fail(reason)
```

运行时接收决策后仍需要校验、授权、物化和持久提交。只有运行时提交后的状态转换和事件才属于可靠执行事实。

## 执行框架步骤是契约边界，不是领域实体

运行时每次调用执行框架，都可以理解为一次执行框架步骤：

```text
决策上下文
   +
策略状态
   ↓
执行框架步骤
   ↓
决策
   +
新的策略状态
```

执行框架步骤的含义是：

> **从一个稳定决策点开始进行一次完整策略求值，直到产生下一个需要运行时接管的决策。**

因此：

```text
执行框架步骤
≠ 一次模型调用
≠ 一次 Agent Turn
≠ 一个工作流节点
≠ 一次规划器步骤
```

一个执行框架步骤内部可以包含多次模型调用、上下文选择、规划、路由、反思、批评和纯策略控制转移，只要这些行为仍然从属于形成当前决策，而且不需要独立可靠执行生命周期。

## 决策上下文是输入投影，不是运行时状态

执行框架不应直接读取运行时数据库、事件表、队列、租约、检查点内部结构或执行器进程信息。

运行时和平台应向它提供面向决策的输入投影，概念上可以包含：

```text
当前执行作用域
本次唤醒原因
新的观察
当前可用能力
预算 / 截止时间 / 自主约束
必要的历史、制品和资源引用
```

执行框架消费的是执行语义，而不是存储表示。

同时：

```text
决策上下文
≠ 模型上下文
```

决策上下文是平台提供给执行策略的输入；执行框架内部的上下文策略再决定当前模型真正加载什么。

## 运行时边界是语义边界，不是 I/O 边界

不能用“是否发生外部 I/O”判断一个行为是否必须进入运行时。

普通模型调用、记忆召回、上下文检索、能力发现或只读语义查询，即使涉及网络和成本，也可以是一次执行框架步骤内部的策略计算。

真正需要跨入 L3 的，是需要独立可靠执行语义的行为。典型判断条件包括：

- 产生需要治理的工作世界效果；
- 需要独立持久生命周期；
- 需要跨进程等待和恢复；
- 需要取消、重试、结果核对或补偿；
- 需要审批或授权；
- 创建其他执行可以依赖的独立执行单元；
- 宣布当前运行完成或失败；
- 跨越权限主体或治理边界。

因此：

> **运行时边界是可靠执行语义边界，而不是网络调用边界。**

## 决策语义

### Execute

`Execute(actions)` 表示执行框架希望运行时产生一个或多个逻辑动作。

`Execute` 整批原子接受或拒绝；合法但待审批的动作可以先物化，未获批前没有派发权限。审批拒绝、超时、过期或撤销按 [审批收口协议](./l3-runtime#_8-2-审批决定与动作收口) 结束未获准派发的动作并反馈策略；重新申请必须创建新动作，不能复活旧终态。审批通过也不免除派发时对当前授权、停止标记和资源准入的检查。

同一次 Execute 中的多个动作表示它们没有执行框架层面的顺序依赖，但不要求物理上必须并行。单体实现可以串行推进，分布式实现可以并行推进，生命周期和物理调度由运行时与工作环境决定。

动作之间存在策略依赖时，应通过后续执行框架步骤继续决策，而不是在 Decision 中重新构造完整 DAG。

### 并发动作的唤醒与定向取消

第一版在任一动作产生新的判定结果，或进入需要策略处理的结果未知状态时，使运行具备再次决策的条件；不隐式等待整批动作全部完成。多次变化可以合并为一次唤醒，但决策上下文必须包含未消费的变化及活动动作 / 子运行的状态投影。运行时内部的瞬时错误和安全重试不必逐次唤醒策略。

执行框架需要等待全部或部分动作时，可以返回 `Wait(AllTerminal(ids))` 或 `Wait(AnyTerminal(ids))`。结果未知不算已完成；它通过异常唤醒交还策略处理。用户纠偏、取消和治理中断也不受普通等待条件阻挡。

`Cancel(targets)` 表示请求停止指定的活动动作或结构化子运行，当前运行仍可继续；它不直接修改目标状态，也不表示取消成功。目标引用必须显式区分动作与子运行，L3 校验目标归属并持久化请求。重复请求可安全去重；目标已终止时返回其当前事实。

- 动作：L3 阻止新的执行尝试，经 L2 请求取消在途尝试，并继续核对真实结果。
- 结构化子运行：L3 启动该子运行的运行取消协议，处理其等待条件、活动动作及下级子运行；不通过 L2 直接取消运行。即使子运行正在等待且没有任何 L2 执行，也能取消。
- 独立子运行：需要独立控制授权，不随父运行隐式取消。

例如 A、B 并行，A 失败后运行时唤醒 L4；L4 可请求取消 B，再等待 B 的实际结果并选择替代路径。整次运行取消仍属于外部运行时控制面，无需策略先返回决策。

### Wait

`Wait(condition)` 只表达：

> **当前策略不需要产生新的动作，希望在已有或时间性条件满足后继续决策。**

执行动作自然导致的等待不需要重复表达：

```text
Execute(A)
→ A 进入未完成状态
→ 运行时挂起当前运行
→ A 达到可继续状态
→ 运行时重新调用执行框架
```

因此：

```text
执行引起的等待
→ L3

策略主动声明的等待
→ L4
```

### Complete

`Complete(output, evidence_refs)` 表示执行策略认为本次运行已经没有更多策略步骤需要推进。

它只是完成提议：

```text
Complete
≠ RunCompleted
≠ WorkCompleted
≠ Accepted
≠ Published
```

运行时仍需检查活动动作、结构化子运行、必要验证和治理门禁后，才能提交运行完成事实。

### 完成门禁与拒绝反馈

所有决策的去重、接受 / 拒绝、输入确认及后继调度遵循 [L3 统一提交协议](./l3-runtime#_11-2-所有决策共用一个提交协议)，完成不能绕过该协议。

必要完成条件由工作单元 / 能力契约及治理要求提供，L3 向决策上下文投影当前条件、证据要求和未满足项，L4 不能自行降低强制要求。

`Complete(output, evidence_refs)` 引用针对交付目标版本的验证证据。L3 检查活动执行、本运行及结构化子树未收敛的执行占用 / 预留 / 释放责任、结构化子树中遗留的未知效果、受信验证证据与目标版本 / 验证条件的关联及治理门禁；未满足时返回结构化的 `CompletionRejected`，包含未满足条件、失效证据或活动执行引用，运行不进入完成终态。

被拒绝的完成提议不提交其新策略状态；L3 记录拒绝事实，并从此前已提交的策略状态发起下一次求值。L4 据此补充验证动作或等待。对没有新输入、没有证据变化的相同提议，不立即重复唤醒，避免空转；持续无进展时进入显式干预。

平台强制验证若由 L3 启动，必须使用预先声明的门禁流程，并建立受治理动作及执行尝试；L3 不临时推导业务补救策略。验证执行仍属于 L2。完成提交绑定被验证的交付版本，不声称外部世界此后永不变化。

### Fail

`Fail(reason)` 表示执行策略认为当前目标已经没有合理继续路径。

它不等于模型调用失败、动作失败、超时或执行器异常：

```text
ActionFailed
→ 执行框架仍可以选择其他策略

Fail
→ 当前策略提出终止运行
```

接受 `Fail` 同样需要通过决策快照与运行许可校验。第一版采用确定性终止规则：L3 原子提交运行 `Failed`、新策略状态与已处理输入确认，同时禁止新策略步骤、新动作、新尝试以及尚未获准派发的尝试继续派发，并持久登记活动动作和结构化子运行的取消请求。L3 随后按各自取消协议推进；独立子运行不隐式取消。

运行可以先进入 `Failed`，不等待取消或结果核对完成。已获准派发但结果未确认的尝试按在途执行处理，不能假定没有副作用；实际成功仍记录成功。取消、核对和资源释放由持久控制记录驱动，崩溃恢复后继续，不恢复失败运行的策略，也不为原动作创建重试尝试。必要的补偿须由另行授权的恢复运行承担。具体规则见 [L3 失败终止协议](./l3-runtime#_14-1-失败终止协议)。

## 控制权转移必须按实际行为区分

“换了哪个 Agent”本身不是运行时边界。需要区分三类不同的控制变化：

```text
策略控制转移
→ 谁负责下一步决策

执行生命周期转移
→ 是否创建新的独立运行、等待、取消和恢复关系

权限转移
→ 是否改变有效身份、能力授权或真实资源可达范围
```

### 纯策略控制转移

例如路由器切到代码专家、规划器切到执行器、一个策略模式切换到另一个策略模式。

如果仍然是同一个运行，没有新的独立生命周期、等待关系和权限主体，那么它只是 L4 内部策略行为。跨多个执行框架步骤仍需保留时，可写入策略状态；运行时无需理解其内部含义。

### 独立执行生命周期

如果委派创建了一个能够独立运行、挂起、恢复、取消和完成的子执行，则必须通过 L3 建立独立子运行和父子关系。

因此：

```text
策略切换
≠ 子运行

Agent-as-Tool
≠ 天然等于动作

Subgraph
≠ 天然等于子运行
```

是否进入 L3，取决于实际生命周期，而不是调用表面名称。

### 权限变化

策略控制转移不能自动带来权限转移。即使执行框架切换到“财务专家”等策略角色，也不能因此获得新的付款、删除或外部系统写权限。

权限变化仍必须经过安全与治理判断，并由 L3/L2 在执行边界落实。

## Workflow、Agent、PTC 和多智能体如何统一

L4 不为不同执行范式建立不同运行时。

### 工作流

工作流图、当前节点和分支逻辑属于执行策略。持久等待、恢复、动作可靠性属于 L3。

### 智能体循环

“智能体循环”是一个复合行业术语。架构上应拆成：

```text
决策策略
→ L4

决策循环的推进与生命周期
→ L3
```

因此 L4 不拥有一个无限的 `while true` 执行生命周期；运行时在新的决策点重新调用执行框架。

### PTC

PTC 决定“这一步是逐个选择能力，还是生成程序批量编排能力”，属于执行策略。真正程序执行仍通过 L3 动作和 L2 执行器进入受治理执行世界。

### 多智能体

多智能体至少区分：

```text
内部 specialist / policy switch
→ L4

没有独立生命周期的子策略计算
→ L4

有独立等待 / 恢复 / 取消语义的子智能体
→ L3 子运行
```

因此 Multi-Agent 不需要另一套运行模型。

## 并发与完成

执行框架负责表达哪些动作在策略上相互独立，运行时决定它们如何实际推进。

```text
Run 单写者
≠ Run 内部串行
```

同一个运行可以包含多个并行动作或结构化子运行。什么时候快速失败、是否聚合部分结果、是否继续其他分支等属于策略；活动执行的等待、取消和恢复属于运行时。

## 恢复、版本与一致性

策略状态的语义和 Schema 由执行框架拥有。运行时负责可靠保存、恢复和引用，但不解释计划、待办、工作流节点等内部结构。

运行必须保留足够的执行框架修订来源，以便恢复、调试和评估。恢复时不要求永远运行历史二进制版本，但必须有明确兼容策略：

```text
兼容
→ 直接恢复

可迁移
→ 由执行框架迁移策略状态后恢复

不兼容
→ 拒绝静默恢复，进入显式干预 / 重启策略
```

不能在恢复时无记录地跨越不兼容执行框架版本。

另外，一个被运行时接受的决策与该决策产生的新策略状态必须共享一致的持久化边界。否则崩溃恢复后会出现“策略认为动作已经发出，但动作并不存在”或相反的状态漂移。

### 会话级策略状态的并发约束

运行单写者只能保护该运行，不能保护多个运行共享的会话级策略状态。第一版同一会话的执行框架步骤从读取策略状态、求值到提交串行化；多个运行的动作仍可在 L2 并行。子会话拥有独立策略状态。

L3 为每个运行持久维护 `decision_context_revision`，它是决策输入快照的版本，不只是纠偏 / 中断版本。开始求值时以一致快照读取决策输入、该修订号及策略状态版本。以下事实进入该运行的合法决策输入时，必须与事实投影的持久更新一起推进修订号：动作的新判定结果或需策略处理的结果未知状态；结构化子运行改变等待、聚合或完成条件的生命周期变化；已路由到该运行的外部信号及审批结果；用户纠偏；改变允许决策集合的授权、治理、预算或截止时间变化。会话级纠偏必须推进该会话内所有受影响运行的修订号，即使策略状态尚未更新、运行仍在执行。此处接收指输入已完成路由并对运行生效，不是入口仅保存待路由载荷。输入生效不等待长时间的策略求值结束，只与短时提交共享一致性边界。修订号推进时原子使该运行当前求值失效并释放会话逻辑位置；最新快照求值按资源额度调度，旧物理调用仍占用预算，迟到返回不能提交。

提交决策时，L3 在同一原子边界比较决策上下文修订号、策略状态版本及运行许可。还须校验当前有效求值身份，重复提交返回持久回执，详见 [统一提交协议](./l3-runtime#_11-2-所有决策共用一个提交协议)。任一不匹配，则整个决策、新策略状态及其动作均不得提交，输入也不确认消费，基于最新上下文重新求值。日志、心跳、执行百分比等不改变合法决策输入的纯进度信息可不推进修订号；分类由运行时确定，不由模型选择忽略新事实。新增业务执行的截止时间必须在提交及派发时再次按时钟校验，不能依赖可能延迟的定时器通知；停止与核对控制不因业务预算 / 截止时间失去执行能力。已接受动作保持有效：普通纠偏不自动暂停排队动作，只有明确的动作 / 运行取消控制才能阻止其后续派发；需要立即停止时不等待 L4 下一轮求值。详见 [派发与纠偏规则](./l3-runtime#_8-3-派发许可与结果接收)。事实更新与提交由该原子边界定序：先更新则拒绝旧决策；先提交则保留已提交事实，按新输入决定后续处理，必要时走取消 / 补偿协议，不撤销历史。崩溃后未提交的步骤可以重新求值，不保证模型产生相同答案，但不得已经派发未提交的工作世界动作。

核心不变量是：只要新事实改变本次决策的合法输入快照，旧决策就不能基于旧修订号提交。例如 A 在模型求值期间从执行中变为成功，基于“A 尚未完成”产生的 B 动作必须随旧决策整体拒绝，重新求值。

未来若允许同一会话并行求值，必须以版本比较保证冲突决策及其动作整体不提交，并基于最新输入重新求值；不能只合并策略状态而保留旧动作。

## 核心不变量

1. **L4 负责策略控制，L3 负责执行生命周期控制，L2 负责真实执行。**
2. **执行框架决策是意图，不是运行时事实。**
3. **执行框架步骤不是模型调用、Agent Turn 或工作流节点，而是一次完整策略求值。**
4. **运行时边界由可靠执行语义决定，不由是否发生 I/O 决定。**
5. **策略状态与运行时状态、会话历史、记忆和工作空间状态必须分离。**
6. **策略状态必须具有明确作用域，不能作为无边界长期记忆。**
7. **纯策略控制转移可以留在 L4；独立执行生命周期必须进入 L3。**
8. **策略控制转移不自动带来权限转移。**
9. **执行引起的等待由 L3 管理；Wait 只用于策略主动声明等待。**
10. **Complete 是完成提议，不等于运行完成事实。**
11. **Plan、Todo、Graph、Reflection、上下文策略、PTC、多智能体都是策略实现，不是 L4 Core primitive。**
12. **L4 不定义统一内部状态机；不同策略通过统一决策边界接入稳定运行时。**
