# L4 / L3 / L2 执行契约审查

本次审查保留现有分层：L4 决策、L3 管理可靠执行生命周期、L2 执行与观察世界。以下逐项记录设计缺口、采用的修订及验证场景；场景是后续实现的验收要求，不代表已有运行时代码通过测试。

## 1. 并发动作如何交还策略控制

**问题成立。** 原设计将快速失败、部分聚合交给 L4，但没有定义批量 Execute 的唤醒规则，也没有定向取消入口。如果默认整批完成后才唤醒，A 失败而 B 长时间运行时，策略无法及时干预。

**修订：**默认在新的动作判定或需策略处理的结果未知状态到达时唤醒；L4 可通过终态组合条件等待，或用 `Cancel(targets)` 请求停止指定执行。运行时内部安全重试不逐次暴露为策略决策点。

**取舍：**增加一个必要的控制意图，不引入 DAG；取消仍由 L3/L2 执行，L4 不获得直接修改生命周期的权限。

**验收场景：**A、B 并行，A 失败后可观察 B 仍在运行；取消 B 后仍等待真实结果；B 恰好完成时不得把成功改写为取消。

参见 [L4 并发契约](../l4-strategy-harness#并发动作的唤醒与定向取消)。

## 2. 数据库提交如何衔接真实副作用

**问题成立，但不能承诺通用的恰好一次执行。** 数据库原子提交不能覆盖外部 API；仅生成幂等键，也不能使任意 Shell 命令具备去重能力。

**修订：**先持久化待派发记录再执行，区分同一次尝试的重送与新的尝试；L2 声明去重、查询和取消能力。响应丢失时按稳定身份核对，无法确认的非幂等动作保留结果未知并请求干预。

**取舍：**第一版复用运行时存储，无需消息队列；可靠性上限由目标系统与执行器实际保证决定。

**验收场景：**分别在提交前、提交后派发前、远端受理后响应前、结果提交前崩溃；恢复不得漏掉已提交意图，也不得盲目重复非幂等副作用。运行终态后仍可核对遗留动作。

参见 [L3 派发协议](../l3-runtime#_8-1-持久派发与结果核对)、[L2 能力声明](../l2-work-environment#_6-1-执行器的恢复能力声明)。

## 3. 等待如何避免丢失唤醒

**问题成立。** 在读取条件与登记等待之间到达的信号，若只通过内存通知交付，可能被永久错过。

**修订：**信号持久化并去重；等待登记与事实重查处于同一一致性边界；输入消费随接受的决策提交。状态条件可重查，时间条件保存绝对截止时间，控制面中断不被普通等待阻挡。

**取舍：**只统一有限结构化条件，不保存闭包，也不向 L4 暴露事件表偏移。

**验收场景：**信号在登记前、登记中、登记后到达均能继续；重复信号不重复消费；恢复时过期定时器立即就绪；拒绝决策不丢弃其输入。

参见 [L3 等待协议](../l3-runtime#_11-1-等待登记与可靠唤醒)。

## 4. 会话级状态如何避免并发覆盖

**条件性问题：**只要同一会话允许多个运行重叠，运行单写者就不足以保护共享策略状态；原设计没有禁止这种重叠。

**修订：**第一版串行化同一会话的完整策略步骤，提交时检查版本和运行许可；动作仍可并发。未来并行求值时，冲突决策及动作必须整体拒绝并重新求值。

**取舍：**同一会话的长策略求值会延迟其他策略步骤；不通过锁住动作执行来扩大阻塞，取消控制面仍可处理。跨会话策略状态互不共享。

**验收场景：**同会话两个运行更新游标，不出现丢失更新；求值中被取消，旧决策不能提交动作；崩溃重求值不会派发未提交动作。

参见 [L4 一致性规则](../l4-strategy-harness#会话级策略状态的并发约束)。

## 5. 完成提议被拒绝后如何继续

**问题成立。** 必要验证的来源、拒绝后的状态及补救责任未明确，可能让 L3 越界决定业务策略，或让 L4 重复提出同一完成提议。

**修订：**上层契约和治理声明完成要求，L3 投影要求并检查版本化证据；拒绝返回结构化未满足项，保留已提交策略状态。L4 决定补充动作，平台强制验证只能执行预定义门禁流程。

**取舍：**完成绑定具体交付版本，不保证外部世界持续不变。相同输入下重复拒绝不立即空转，持续无进展转显式干预。

**验收场景：**证据缺失、版本失效、仍有活动执行时不能完成；补充验证后可重新提交；不能因拒绝而把策略游标提前推进。

参见 [L4 完成门禁](../l4-strategy-harness#完成门禁与拒绝反馈)。

## 6. 本地并发是否需要资源协调

**问题成立，但不需要提前建设分布式工作空间服务。** 同一进程内的并行动作也能覆盖文件；策略独立性不等于资源独立性。

**修订：**默认串行写入共享工作空间，未知访问范围按独占写处理。完成验证使用稳定快照或阻止并发写；重启后核对旧执行再释放占用。外部主体修改通过版本 / 快照处理，数据库等资源使用自身并发控制。

**取舍：**默认牺牲部分并行吞吐以换取清晰语义；隔离工作副本或证明资源互不冲突后允许并行。

**验收场景：**两个 Shell 写同一文件不会同时准入；验证期间修改不能沿用旧证据；运行时重启而旧进程仍在写入时，新动作不得抢占同一资源。

参见 [L2 本地并发](../l2-work-environment#_14-3-共享工作空间的本地并发约束)。
