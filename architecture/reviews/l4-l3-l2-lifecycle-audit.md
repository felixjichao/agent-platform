# L4 / L3 / L2 生命周期一致性审查

此前按评论逐项补充，缺少跨协议的时序审查，导致局部规则成立而组合后仍有缺口。此处从状态所有者、提交边界、并发顺序和崩溃恢复重新核对第一版设计。它记录人工时序推演及实现验收要求，不是形式化证明，也不代表运行时代码已通过故障注入测试。

## 审查范围与前提

第一版是单个活动运行时协调者、一个支持事务和唯一约束的运行时存储，以及可同步或异步执行的 L2。L2 可以使用外部系统，但不能假设其与运行时数据库共享事务。多运行、异步回调、控制输入和进程崩溃均在范围内；多活动协调者的租约接管不是本次实现承诺。

模型求值不在数据库事务中运行。运行时内部提交可以原子化，真实副作用不能回滚成“从未发生”。无法核对时允许持久阻塞和显式干预，不承诺所有工作最终自动成功。

## 状态所有者与提交边界

| 边界 | 权威状态与负责方 | 同一次提交必须包含 | 提交外的行为 |
| --- | --- | --- | --- |
| 入口接收 | L3 入口记录 | 来源、稳定身份、载荷引用、去重结果 | 尚不能宣称输入已对运行生效 |
| 路由 / 控制输入生效 | L3 路由与运行 | 目标集合、必要的新运行、输入绑定、修订号、待唤醒 / 停止标记 | 不等待模型结束 |
| 开始求值 | L3 求值协议 | 当前有效求值身份及快照关联 | L4 进行策略计算，不直接派发副作用 |
| 接受或拒绝决策 | L3 运行时存储 | 回执、有效身份关闭；接受时另含状态、输入确认、决策效果与调度 | L2 尚不因此自动获得派发许可 |
| 派发许可 | L3 尝试与 L2 准入 | 当前约束检查、尝试关联的持久资源占用 / 许可 | 外部准入分存储时需幂等预留与核对，不虚构跨存储事务 |
| 结果接收 | L3 执行事实 | 结果去重、尝试 / 动作判定、修订号、待唤醒 | L2 提供原始证据，摘要可异步形成 |
| 运行终止 | L3 运行控制 | 终态或停止标记、未决控制工作、事件 | 取消 / 核对 / 资源释放独立于策略生命周期继续 |

三种版本不能混用：求值身份限制哪次计算仍有效；输入修订号限制它基于哪些事实；策略状态版本限制它可以更新哪份策略状态。任意一项缺失，都可能接受不应接受的返回。

## 必须保持的不变量

1. 一个入口身份只有一个已提交路由结果；一个求值身份只有一个处理回执，同一返回重送不能再次创建动作。
2. 未提交决策不得产生真实执行；提交成功也不等于已获准派发。
3. 输入变化、决策提交和终止请求必须能在相应运行控制边界定序，不能以迟到的异步视图替代权威状态校验。
4. 明确拒绝不得推进候选策略状态或消费输入；接受只确认快照内明确处理的输入。
5. 运行 / 动作停止后不得新获派发许可；此前已获准的执行按可能已经发生处理，不能靠终止状态否认副作用。
6. 重复、乱序结果不能回退权威状态；结果未知不是安全重试或释放资源的证据。
7. 完成、失败、取消拥有明确且不同的终态条件；先提交的终止路径不能被迟到决策改写。
8. 恢复必须覆盖待路由、待派发、待审批、待唤醒、待核对和待释放工作，不只恢复非终态运行的策略。

## 并发与崩溃时序矩阵

每个跨边界场景同时检查两种提交顺序；恢复以持久记录为准，模型返回值和进程存活不作为事实来源。

| 场景 | 合法顺序与预期结果 | 崩溃 / 重送后要求 |
| --- | --- | --- |
| 会话没有活动运行时收到输入 | 路由原子创建运行与输入绑定；并发入口在会话作用域串行判定 | 已提交路由复用目标，不重复建运行 |
| 输入路由与 Complete 竞争 | 路由先提交则旧 Complete 过期；Complete 先提交则路由重新判断目标 | 明确指向终态运行的控制不误投新运行 |
| 入口已保存但尚未路由 | 只确认接收，不能宣称纠偏已生效；已知目标控制尽量同事务生效 | 待路由记录恢复处理，不丢失输入 |
| 模型求值中动作完成 / 审批到达 | 新事实先提交则旧决策拒绝；决策先提交则事实进入下一次决策 | 结果事实与修订号、唤醒一起恢复 |
| 同一决策响应重送 | 按求值身份和内容返回原回执，不再次创建动作 | 提交响应丢失先查回执 |
| 旧模型请求在恢复后返回 | 恢复替换有效求值身份，旧返回不能提交，即使输入内容未变 | 新旧进程不同时拥有有效提交身份 |
| Execute 中一项请求非法 | 整批拒绝；需要审批但合法的动作可整批物化为待审批 | 拒绝无部分动作，待审批无派发许可 |
| 排队后授权撤销 / 预算耗尽 | 派发时重新检查，未获准尝试不执行 | 恢复派发也检查当前约束，停止控制仍可运行 |
| 终止与派发许可竞争 | 终止先提交则拒绝许可；许可先提交则按在途执行取消 / 核对 | 缺少响应不等于未执行，控制记录不丢失 |
| 子运行委派响应丢失 | 子运行与委派关系原子唯一创建 | 恢复复用子运行，不因重送再次委派 |
| 结果重复或乱序 | 重复不新增事实，旧进度不覆盖终态；矛盾证据进入核对 | 不使用最后写入覆盖结论 |
| 旧写入状态未知时请求重试 | 没有同身份去重则不启动重叠尝试；自然幂等不足以解除共享写阻塞 | 原资源持续阻塞，直到停止或隔离证据成立 |
| 信号在 Wait 登记前后到达 | 事实先持久化，登记原子重查；两种顺序都能继续 | 消费只确认已处理引用，关联键不跳过其他信号 |
| 广播与等待重建 | 路由时固定目标，每个运行独立消费 | 重建等待不重新消费，未来运行不获得历史广播 |
| 定向取消等待中的子运行 | L3 运行取消协议处理，无需存在 L2 执行 | 持久请求继续处理，不要求唤醒子策略 |
| Complete 与外部取消竞争 | 先提交路径胜出；已接受运行取消使在途策略返回失效 | 终态不可回退，后到请求返回当前事实 |
| 子运行 Failed 但动作仍 Unknown | 父 Complete 不得只因子运行终态而通过 | 核对工作独立存在，父门禁看到未决效果 |
| Failed 后取消 Shell 前崩溃 | 控制恢复直接扫描持久取消、核对与资源占用，不能从非终态运行列表派生 | 完成停止与核对后释放占用，原运行仍保持 Failed |
| 父取消而子运行无执行、仍在等待 | 父取消完成必须等子运行自己的 L3 终态转换，不能只看执行尝试为空 | 重启继续子运行取消，记录终态和资源收敛后父级才 Cancelled |
| 已接受动作排队期间普通纠偏 | 选择已接受动作保持有效，普通纠偏不阻止派发；明确取消控制先提交才阻止许可 | 审批通过仍按当前准入执行，不将输入修订号变化当隐式取消 |
| Fail 时仍有并行执行 | 原子关闭新执行并持久登记取消，可先进入 Failed | 只继续控制收敛，不恢复失败策略或原动作重试 |
| 运行取消但无法确认旧执行 | 停止标记生效，保持取消处理中，不误报 Cancelled | 资源不自动释放，显式干预原因可查询 |
| 重复拒绝 / 已满足等待导致空转 | 达到无进展上限挂起并保留原因；控制面可继续 | 重启不清零限制以绕过预算，也不无限重试 |
| 取消中收到新的会话任务 | 停止中的旧运行不接收策略输入，允许新建运行；显式指定旧目标则拒绝投递 | 路由与停止定序，新运行不绕过旧执行的资源阻塞 |
| 输入更新时旧模型长期未返回 | 修订与过期标记、逻辑位置释放原子提交；最新快照按额度调度 | 旧调用仍计入资源，迟到结果不能提交或释放新位置 |
| 审批拒绝 / 过期 / 撤销 | 无派发许可则明确失败，反馈策略；有许可则按在途核对 | 持久截止时间恢复检查，迟到批准不复活终态，新申请必须新动作 |
| 授权撤销 / 资源暂忙 / 预留未知 | 分别明确终止、带截止等待、阻塞核对；不得统一永久排队 | 恢复保留分类、期限和资源责任；未派发失败不伪造尝试执行结果 |
| 无尝试的审批拒绝 / 准备后未派发 | 动作可有零次尝试；准备记录不表示执行已发生 | 判定引用执行前事实；许可与 Dispatched 原子提交，之后才触达 L2 |
| 连续并行动作完成 | 旧决策立即失效，单一待调度项合并至最新修订，限制模型重启频率 | 合并期限不因新输入无限后移，达到无进展上限显式干预 |
| 许可已提交但 L2 尚未收到时取消 | 旧派发责任未收敛前，查无执行不能证明取消完成；可靠封禁或交付收敛才放行 | 崩溃恢复扫描派发责任，不能取消完成后又让旧请求执行 |
| L2 在 Dispatched 后拒绝 | 可信执行前拒绝使尝试终止且不复用；暂时原因经新准入创建新尝试，证明不足则未知 | 拒绝证明须覆盖迟到请求，历史副作用与资源责任不丢失 |
| 当前判定与迟到矛盾证据 | 追加判定事件及版本，未知为非终态；终态矛盾另记异常并阻止未完成父级通过门禁 | 重复证据不重复唤醒，终态不回退、原历史不覆盖 |
| 验证之后目标再次变化 | 完成绑定受信验证的明确版本；未处理输入或未决执行阻止完成 | 不把旧证据当作新版本通过，不凭模型引用放行 |

## 本次收敛的修订

此前没有统一处理的缺口集中在五处：决策重复提交与迟到返回、接收和路由的生效差异、派发时重新准入、回调与重试的次序、三种终止路径的仲裁。本次将规则放在 L3 的共享协议章节，L4 和 L2 引用其语义，不为每个决策再维护一套独立版本。
