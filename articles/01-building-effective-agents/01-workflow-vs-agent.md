# 工作流与智能体的真正区别

## 文章中的关键观点

文章区分了两类系统：

- **工作流（Workflow）**：模型和工具按照预定义的代码路径执行。
- **智能体（Agent）**：模型动态决定自己的执行过程和工具使用方式，并保持对任务完成方式的控制。

文章强调应优先采用简单、可组合的模式，只有当任务需要更强的灵活性和模型驱动决策时，再增加智能体自主性。

## 我们的架构分析

“对话、科研、知识库、Coding”等是**应用形态**；“直接调用、工作流、智能体”是**执行范式**。两者不能混为一谈。

真正稳定的边界不是“是否用了 Agent 框架”，而是：

> **谁拥有执行控制权。**

工作流的下一步主要由代码决定；智能体的下一步主要由模型根据当前状态动态决定。两者可能使用完全相同的模型、工具和数据源。

因此，一个企业知识库既可能是一次检索后直接回答，也可能采用固定工作流，还可能让智能体自主研究。产品名称无法决定运行时模型。

## 对 Agent Platform 的影响

平台首先应该把“应用定义”和“执行策略”分离：

```text
应用 / 业务目标
      ↓
执行策略
      ↓
统一运行时
```

执行策略可以选择直接执行、工作流或智能体循环，而不是让每一种产品重新实现运行时。

## 核心结论

> **应用形态不等于执行范式；工作流与智能体的核心区别是执行控制权归属。**
