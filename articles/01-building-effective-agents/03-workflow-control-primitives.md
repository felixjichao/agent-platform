# 工作流模式可以归约为控制流原语

## 文章中的关键观点

文章列出的典型工作流模式包括提示链、路由、并行化、评估者-优化者以及编排者-工作者等。

## 我们的架构分析

这些模式不必分别实现成五套运行时机制，可以进一步归约成少量控制流原语：

| 文章模式 | 更基础的运行时控制原语 |
| --- | --- |
| 提示链 | 顺序执行（Sequence） |
| 路由 | 条件分支（Branch） |
| 并行化 | 分叉 / 汇合（Fork / Join） |
| 评估者-优化者 | 循环 + 分支（Loop + Branch） |
| 编排者-工作者 | 动态展开（Dynamic Expansion） |

这说明工作流 DSL、DAG 或可视化编排器更适合作为上层表达，而不是统一运行时的数据模型本身。

尤其“编排者-工作者”已经出现动态性：工作项数量和内容可能在运行时才生成。这是工作流向智能体过渡的重要桥梁。

## 对 Agent Platform 的影响

执行层应提供可组合的控制能力，而不是为每个模式建立一套专用引擎。上层工作流可以编译或解释成这些基础操作，智能体也可以动态产生同样的执行结构。

## 核心结论

> **典型工作流模式可以被统一理解为少量控制流原语的组合；工作流图是输入表达，不必成为运行时事实模型。**
