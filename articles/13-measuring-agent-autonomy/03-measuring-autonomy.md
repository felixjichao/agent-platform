# 自主性是测量投影，不是运行时事实

## 文章中的关键观点

Anthropic 没有试图用一个绝对分数定义自主性，而是使用多种代理指标观察真实部署行为。

Claude Code 中可以直接观察一次连续工作片段持续多久、何时被人打断、何时由 Claude 主动停止并询问。文章指出，回合时长只是自主性的一个不完美代理指标：模型速度、任务难度、子智能体并行以及产品效率都会影响它。

一些代表性数据包括：

- Claude Code 的中位回合时长约 45 秒，大多数低于 99 分位的时长相对稳定；
- 99.9 分位的回合时长约 42 分钟；
- Anthropic 内部最困难任务的成功率从 8 月到 12 月翻倍，同时平均每会话人工干预从 5.4 次下降到 3.3 次。

这些数据说明，连续运行更久本身并不等于更好的自主性；必须同时观察是否取得可靠结果、是否在正确的时候请求帮助。

## 我们的架构分析

相比一个静态的 `autonomy_level = 7`，平台更应该记录构成自主性的真实事实：

```text
运行
├── 自主执行片段
├── 动作
├── 人工审批
├── 人工中断
├── 人工纠偏
├── 智能体主动升级
└── 最终结果
```

再基于这些事实形成测量投影，例如：

```text
自主性指标
├── 连续自主执行时长
├── 每个自主片段的动作数
├── 人工干预次数
├── 审批率 / 中断率 / 纠偏率
├── 智能体主动升级率
├── 自主完成率
├── 验证通过率
└── 单次成功自主结果成本
```

重要的是，不能把“减少人工干预”本身当作优化目标。必要的澄清、升级和停止属于正确行为。

## 对 Agent Platform 的影响

自主性指标应该从事件和追踪中计算，而不是直接写成运行时事实：

```text
运行 / 动作 / 控制权转移事件
              ↓
         自主性投影
              ↓
        指标 / 看板
```

这与评估分数的建模方式一致：

- 最终结果是事实，评估分数是测量投影；
- 控制权转移是事实，自主性指标也是测量投影。

## 核心结论

> **不要问“这个智能体的自主等级是多少”，而要观察它能独立推进多久、人在什么地方介入、智能体何时主动升级，以及这种控制权分配最终带来了怎样的结果和风险。**
