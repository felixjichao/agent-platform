# 人工监督不等于逐步审批

## 文章中的关键观点

Anthropic 在 Claude Code 的真实使用中观察到一个看似矛盾的趋势：用户越有经验，越倾向于开启自动批准，同时也越经常主动打断智能体。

文章给出的数据包括：较新的用户在大约 10 个会话时，约 5% 的回合会主动打断 Claude；更有经验的用户约为 9%。另一方面，少于 50 个会话的用户大约 20% 的会话会使用完全自动批准，到约 750 个会话时这一比例超过 40%。

Anthropic 的解释是：熟练用户并不是放弃监督，而是从“每一步事前审批”转向“让智能体持续工作、必要时再中断和纠偏”的监督方式。

文章还发现，任务越复杂，Claude 越倾向于主动停止并请求澄清。在最复杂的任务中，Claude 主动澄清的频率超过人工打断频率的两倍。智能体主动停下来咨询人类，本身也是部署系统中的一种监督机制。

## 我们的架构分析

“人工在环”如果只建模成审批，会把监督能力压缩成一个低带宽开关：

```text
动作
 ↓
是否批准？
 ↓
动作
```

更完整的人工监督至少包括：

```text
人工监督
├── 观察
├── 事前审批
├── 中断
├── 纠偏
├── 澄清
├── 评审
├── 升级
└── 验收
```

这背后的核心不是“人有没有在循环里”，而是执行控制权如何在人、模型和确定性系统之间移动。

```text
人设定目标
   ↓ 委托控制权
智能体持续执行
   ↓ 遇到不确定性 / 风险 / 能力缺口
交还控制权
   ↓ 人补充信息 / 纠偏 / 决策
智能体继续执行
```

因此，成熟的监督机制更适合抽象为**控制权转移（Control Transfer）**。

## 对 Agent Platform 的影响

执行框架负责判断何时应该继续自治、何时应该主动交还控制权，例如：

```text
升级策略
├── 不确定性过高
├── 需求歧义
├── 信息缺失
├── 能力缺口
├── 策略边界
└── 风险边界
```

运行时则提供确定性的控制接口和事实记录，例如：

```text
start
pause
resume
interrupt
cancel
redirect
```

控制权转移不是一句提示词，而必须真正改变后续动作是否还能继续执行。

## 核心结论

> **人工监督不应被建模成单一审批门，而应被建模成执行过程中可动态发生的控制权转移。**

> **好的自主智能体不仅要会继续行动，还必须知道什么时候应该主动放弃自主权。**
