# 部署后监控补足上线前评估

## 文章中的关键观点

Anthropic 明确区分了能力评估与真实部署观察：上线前评估可以测试智能体在受控条件下“能够做到什么”，但无法完整回答真实用户会授予多少权限、如何监督、何时打断，以及智能体何时主动请求帮助。

这也是为什么文章强调部署后监控（Post-deployment Monitoring）。Claude Code 是 Anthropic 自有产品，可以把请求关联到完整会话，因此能够研究连续自主时长、人工中断和主动澄清；公共 API 则缺乏可靠方法把彼此独立的请求重新关联成完整智能体会话，这直接限制了对真实自主行为的理解。

Anthropic 还强调，部署后测量必须在保护隐私的前提下进行，不能把“需要观测”理解成无边界保存用户内容。

## 我们的架构分析

上线前与上线后回答的是两个不同问题：

```text
能力评估
→ 在标准条件下能不能完成？

部署监控 / 部署评估
→ 在真实用户、真实权限、真实任务中实际上怎么运行？
```

因此完整闭环应是：

```text
能力定义
   ↓
上线前评估
   ↓
发布 / 部署
   ↓
部署后监控
   ↓
真实行为 / 失败模式
   ↓
形成新的评估任务
   ↓
回归评估
   ↓
执行框架 / 能力修订
```

这也说明工作（Work）、会话（Session）、运行（Run）、事件（Event）、动作（Action）的统一标识不只是恢复机制，还是智能体测量基础设施。只有能把多个模型请求和工具动作重新关联为执行轨迹，才能理解真实的自主性和人工监督方式。

## 对 Agent Platform 的影响

可观测性不应该只记录提示词、Token、时延或单次工具调用，而要能够形成完整执行轨迹：

```text
工作
 ↓
会话
 ↓
运行
 ↓
控制权委托
 ↓
自主执行片段
 ↓
动作 / 中断 / 纠偏 / 升级
 ↓
最终结果
 ↓
验证 / 验收
```

生产失败应进一步进入“真实追踪 → 失败分析 → 最小复现 → 新评估任务 → 回归套件”的闭环。

## 核心结论

> **上线前评估测量受控条件下的能力潜力；部署后监控测量真实系统里实际发生的行为。**

> **没有工作、会话、运行级的执行关联，就很难形成真正的智能体可观测性，也很难可靠测量自主性。**
