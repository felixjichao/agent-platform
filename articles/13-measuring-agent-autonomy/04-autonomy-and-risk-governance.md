# 自主性必须与风险联合治理

## 文章中的关键观点

Anthropic 对公共 API 中约 99.8 万次随机工具调用进行聚类，并分别估计动作的风险与自主程度。结果显示：高自主和高风险是两个不同维度，当前绝大多数动作仍集中在低风险区域，高自主、高风险区域相对稀疏，但并非不存在。

文章还给出了几个部署侧信号：约 80% 的工具调用来自看起来至少具有一种保护措施的智能体，约 73% 看起来存在某种人工参与，只有约 0.8% 的动作被判断为不可逆。Anthropic 同时提醒，这些数字基于模型分类和有限上下文，其中人工参与比例可能被高估，因此更适合作为趋势信号而不是精确事实。

文章观察到，高风险动作更多出现在安全、金融和医疗信息等领域；随着智能体从软件工程向更多高风险行业扩展，风险与自主性的前沿预计会继续向外扩张。

## 我们的架构分析

高自主不等于高风险：一个只能在沙箱中读资料、跑测试的智能体可以高度自主，但影响半径很小；一个几乎完全由人指挥的动作，也可能因为直接操作生产数据而具有极高风险。

因此至少需要同时观察：

```text
自主性
× 风险
× 可达范围
× 动作后果
```

其中，可逆性是非常重要的风险变量。Git 分支、沙箱、测试、差异审查和回滚机制之所以能支撑更高的 Coding Agent 自主性，本质上是在降低错误动作的不可逆性和影响半径。

更成熟的治理方式不是全局配置“高自主”，而是在动作级动态决定是否继续让智能体持有控制权：

```text
候选动作
   ↓
风险判断
   ├── 低风险 → 自动执行
   ├── 中风险 → 持续观察 / 加强验证
   ├── 高风险 → 控制权转移
   └── 禁止风险 → 确定性拒绝
```

## 对 Agent Platform 的影响

风险判断不能只依赖工具名称，应结合：

```text
动作
× 资源
× 范围
× 可逆性
× 数据敏感度
× 外部影响
× 环境
```

自主策略应受风险边界约束，并与既有隔离配置协同：

- 隔离控制决定“最多能触达到什么”；
- 风险判断决定“当前动作后果有多大”；
- 自主策略决定“当前还能不能继续自己决定”；
- 控制权转移决定“什么时候交还给人或更高层治理机制”。

## 核心结论

> **自主性不应该被全局最大化，而应该在风险、可逆性、可达范围和验证能力约束下动态分配。**

> **提高安全自主性的有效方式之一，是把工作环境设计得更隔离、更可逆、更容易验证。**
