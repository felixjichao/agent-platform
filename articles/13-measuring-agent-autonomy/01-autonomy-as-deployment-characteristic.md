# 自主性是部署特征，不是模型属性

## 文章中的关键观点

Anthropic 将自主性（Autonomy）用于描述智能体在多大程度上可以独立于人的直接指导和监督运行。文章特别强调：自主性不是模型或系统的固定属性，而是一次具体部署中的涌现特征，由模型行为、用户监督策略和产品设计共同塑造。

这意味着能力评估与真实部署不能直接等同。外部评估可以说明模型在理想条件下能够处理多长、多久的任务；真实产品中还存在用户打断、智能体主动询问、权限边界和产品默认设置。Anthropic 将二者之间的差距称为一种部署余量：模型能够承担的自主程度，可能高于真实系统实际授予它的自主程度。

## 我们的架构分析

需要区分两件事：

```text
潜在自主性
→ 模型 + 执行框架理论上能够独立完成多少

实际自主性
→ 在真实权限、产品策略、风险边界和人工监督下实际发生多少
```

因此：

```text
模型能力
   ↓
潜在自主性
   ↓ 受产品策略 / 权限 / 风险 / 人工监督约束
实际自主性
```

同一个模型在“每个动作审批”“受限工作空间内自动执行”“沙箱内长时间无人值守”等部署方式下，会表现出完全不同的实际自主性。

这也修正了执行策略的心智模型。直接执行、工作流、智能体循环、PTC、多智能体回答的是“任务怎么推进”；自主性回答的是“推进过程中，系统允许智能体自己决定多少”。二者不能混为一谈。

## 对 Agent Platform 的影响

自主性不应成为运行时核心实体，也不适合用 `autonomous = true/false` 固化。它更接近执行策略与治理共同形成的动态策略：

```text
工作 / 运行
├── 执行策略
├── 能力边界
├── 隔离配置
└── 自主策略
```

其中：

- 隔离配置回答“最多能触达到哪里”；
- 自主策略回答“在这个边界内可以自己决定多少”。

## 核心结论

> **模型能力决定智能体可能自主到什么程度；执行框架、权限、产品设计和人工监督共同决定它实际自主到什么程度。**

> **自主性不是智能体的静态属性，而是系统动态授予的执行决策空间。**
