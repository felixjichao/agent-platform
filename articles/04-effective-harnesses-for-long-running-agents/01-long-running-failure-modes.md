# 长任务的两类典型失败

## 文章中的关键观点

长时间任务跨越多个上下文窗口时，Agent 容易出现两类问题：

1. 一次试图完成太多内容，直到 Context 临近耗尽，工作停在半途中；
2. 新一轮 Agent 看到已经有不少进展，就误判任务接近完成，过早收尾。

## 我们的架构分析

这两个问题分别暴露了：

```text
当前轮次缺少“可交接的结束策略”
        +
新轮次缺少“可靠的剩余工作定义”
```

因此，长任务不能只优化“这一轮如何做得更多”，还必须优化：

- 什么时候主动停止当前轮；
- 停止前留下什么；
- 下一轮如何确认真实进展；
- 如何避免把“已经做了很多”误判成“已经完成”。

## 对 Agent Platform 的影响

平台应允许 Harness 在 Context 耗尽前主动形成 Checkpoint / Handoff，并重新触发下一轮执行。真正的连续性来自持久工作状态，而不是把一个模型调用无限延长。

## 核心结论

> **长任务设计的核心不是让单次 Context 更长，而是让每次 Context 都能安全结束并可靠续接。**
