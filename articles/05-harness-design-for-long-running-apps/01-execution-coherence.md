# 长任务不只需要连续性，还需要执行一致性

## 文章中的关键观点

文章在长时间应用开发实验中发现，仅仅让 Agent 跨上下文继续工作还不够。系统还需要让每一轮工作围绕同一目标、质量标准和可验证结果持续收敛。

## 我们的架构分析

前一篇解决的是：

> **如何不断续上。**

这一篇进一步解决：

> **续上以后如何保证方向没漂、质量没有被局部进度替代。**

因此长任务需要两种连续性：

```text
Execution Continuity
→ 能恢复并继续

Execution Coherence
→ 多轮执行仍围绕同一个目标和验收标准收敛
```

如果只有前者，Agent 可能非常稳定地持续做错事。

## 对 Agent Platform 的影响

Work / Session 不仅要保存进度，还要保存长期稳定的目标、约束和验收依据，使每个新的 Harness 实例都能重新对齐。

## 核心结论

> **Long-running Agent 的核心不只是连续执行，而是跨轮次保持目标与验收的一致性。**
